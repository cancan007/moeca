# Knowledge タブ 追加依頼 — トレースと最適化

（先に渡した「Knowledge タブ — 設計依頼」の続き。同じアプリ・同じデザイントークン）

Knowledge タブに、**実行済みタスクを振り返ってコンテキストを最適化する**
ための導線を足したい。

---

## 1. 入口 — Audit からの遷移

既存の **Audit** タブには、実行されたタスクがラン単位で並んでいる。
そこに**トレースボタン**を置き、押すと Knowledge タブに遷移して
そのタスクのトレースが表示される状態にしたい。

Audit 側は既存画面なので、**ボタンの置き方の差分だけ**見せてもらえればよい。

---

## 2. トレース表示

グラフビュー（先の依頼のモード A）の上に、
**そのタスクが実際にどのナレッジへ到達したか**を重ねて表示する。

### 2.1 ステージ単位のフォーカス

タスクは複数の**ステージ**に分かれて実行される。
ステージ＝それぞれ別のエージェントだと思ってよい（例: 調査 → 実装 → レビュー）。

- ステージを選ぶと、**そのステージが到達した node だけがフォーカス**される
- 他の node は沈む（グレーアウト／低コントラスト）
- ステージを順に送ると、**参照が移り変わっていくのが見える**
- 「全ステージ」を選ぶと合算表示

### 2.2 遷移が見えること

成果物が出るまでに**どういう順序でナレッジをたどったか**を確認したい。

- ステージのタイムライン／ステッパー
- 同じ node が複数ステージで参照されたことが分かる表現
- 一度も参照されなかった node が分かる表現
  （「このタスクにこの group は要らなかった」という判断につながる）

### 2.3 表示上、正直であってほしいこと

**これは実装上の制約なので、断定的な UI 文言を避けるために共有する。**

**「参照した」ではなく「返ってきた」しか分からない。**
記録できるのは検索結果としてエージェントに渡ったものまでで、
エージェントがその中の何を実際に読んで判断したかは分からない。
**常に上限値**であり、「返ってきたから必要だった」とは読めない。
`参照した` のような断定ではなく `到達` `返却` のような語を使いたい。

**記録が途中で切れることがある。**
ログの記録量に上限があるため、返却量が多いと末尾が欠ける。
**欠落があり得ることを示す表現**（「一部記録なし」など）が要る。

---

## 3. 右ドロワー — システムプロンプトの修正

**この画面の主目的は「トレースを見ながら直せる」こと。**
別画面に移動して直すのでは、見ていたものを忘れてしまう。

- グラフビューの**右からドロワー**が出る
- 選択中のステージの**システムプロンプトを、その場で編集・保存できる**
- ドロワーを出したままグラフを操作できる
  （ドロワーがグラフを覆い隠しすぎない幅・レイアウトにしてほしい）

### 3.1 気をつけてほしい 2 点

**(a) システムプロンプトはエージェントテンプレートに属する。**

プロンプトは**タスクではなくエージェントテンプレート**が持っている。
テンプレートは**他のタスクでも使い回される**ので、
ここで保存すると**そのテンプレートを使う今後の全タスクに影響する**。

「今見ているタスクを直している」ように見えて、実際は共有設定を
書き換えている。**この落差が UI で伝わらないと事故になる。**
影響範囲（このテンプレートを使っているタスク数など）が
保存時に見えるようにしたい。

**(b) 編集しても、今見ているトレースは変わらない。**

トレースは**過去の実行記録**、プロンプトは**次回の設定**。
同じ画面に「変えられない過去」と「変えられる未来」が同居する。
編集内容が今の表示に反映されると誤解させないでほしい。

---

## 4. node の扱い — その場で編集はしない

グラフ上の node をクリックしても、**内容の編集はさせない。**
確認できるのは**場所（リンク・パス）まで**にとどめる。

| ソース種別 | 見せるもの | 導線 |
|---|---|---|
| ローカルファイル | ファイルパス | パスのコピー／エディタ・フォルダで開く |
| 外部ドキュメント | URL | コピー／ブラウザで開く |

### なぜ編集させないか

グラフ上に見えているのは**チャンク**（埋め込みのために機械的に
1200 文字程度で切った断片）で、**人間が見て意味のある単位ではない。**
文の途中で切れていることもある。

チャンクを編集させると、境界の扱い・再分割・再埋め込みが全部絡む。
**修正は元ファイルで行い、Knowledge タブから再インデックスする**
という流れにしたい。

そのため node のインスペクタでは:

- **どのファイル／URL 由来かをはっきり見せる**（これが主役）
- チャンク本文は**参考表示**（読み取り専用、切れている旨が分かるとよい）
- 同じファイル由来のチャンクがまとまって見えるとよい
- 再インデックスへの導線

---

## 5. 成果物

- **Audit にトレースボタンを置いた状態**（既存画面の差分でよい）
- **Knowledge タブのトレース表示**
  - あるステージにフォーカスしている状態
  - 全ステージ合算の状態
- **ステージのタイムライン／ステッパー**
- **右ドロワーでシステムプロンプトを編集している状態**
  - 保存時に影響範囲が見えている状態
- **node のインスペクタ**（パス／URL と読み取り専用のチャンク本文）
- トレースの**記録が欠けている**ときの表示

ダーク優先。

# 決済基盤 設計方針

## 全体像

決済基盤は、注文サービスから受け取った決済要求を外部の決済代行(PSP)へ中継し、
確定した結果を売上台帳へ書き込むまでを担当する。同期で応答を返すのは与信確保までで、
売上確定は非同期のワーカーが行う。

- `payment-api` — 決済要求の受付。冪等キーの検証と与信確保まで
- `settlement-worker` — 確定処理。PSP の webhook を受けて台帳へ書き込む
- `ledger` — 売上台帳。追記のみで、更新も削除も受け付けない

## 冪等性

決済 API はすべて冪等キー(`Idempotency-Key`)を必須とする。同じキーで再送された要求は、
最初の応答をそのまま返す。ネットワーク断でクライアントが再送するのは正常系であり、
二重課金を防ぐ責務はサーバ側にある。

冪等キーの保持期間は 24 時間。それを過ぎた再送は新しい決済要求として扱われる。

## リトライ

PSP への呼び出しは指数バックオフで最大 3 回まで再試行する。タイムアウトは接続 2 秒、
読み取り 10 秒。4xx は再試行しない(要求そのものが不正なので、再送しても結果は変わらない)。
5xx とタイムアウトのみ再試行する。

詳細は [リトライポリシー](retry-policy.md) を参照。

## 台帳の不変条件

- 台帳は追記のみ。訂正は「打ち消しの行を足す」ことで表現する
- 1 決済につき 1 行。冪等キーが主キーになる
- 金額は最小通貨単位の整数で保持する。浮動小数点は使わない

この不変条件を壊す変更は、レビューで必ず指摘すること。過去の障害はほぼすべてここに
起因している。

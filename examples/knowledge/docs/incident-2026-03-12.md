# 障害報告 2026-03-12 二重計上

## 概要

2026-03-12 14:02〜14:41(JST)、`settlement-worker` が PSP の webhook を二重処理し、
売上台帳に 312 件の二重計上が発生した。影響額 4,182,400 円。台帳の訂正行で解消済み。

## 時系列

| 時刻 | 出来事 |
|---|---|
| 14:02 | PSP 側の遅延で webhook が再送され始める |
| 14:09 | 台帳の日次合計アラートが発報 |
| 14:22 | 二重計上と特定。worker を停止 |
| 14:41 | 冪等キー重複を弾く修正をデプロイし、再開 |
| 16:30 | 訂正行 312 件を投入し、合計が一致 |

## 原因

`settlement-worker` が冪等キーの重複チェックを**台帳への書き込み前ではなく後**に
行っていた。PSP の webhook 再送は仕様どおりの挙動であり、再送そのものは異常ではない。

チェックの順序が逆だったため、同じ冪等キーで 2 行が書き込まれ、そのあとで
「重複している」と検知してログに出すだけになっていた。

## 対処

- 冪等キーに UNIQUE 制約を張り、DB 側で二重挿入を拒否するようにした
- アプリ側のチェックは残したが、これは早期リターンのためであって、正しさの根拠は
  UNIQUE 制約側に移した

## 学び

**正しさをアプリケーションのチェックに依存させない。** アプリのチェックは順序を
間違えられるが、DB の制約は間違えようがない。

同じ構図の弱点が `ledger` の他の経路にも無いか、四半期ごとに棚卸しすること。

# リトライポリシー

## 原則

再試行してよいのは、**同じ要求をもう一度送れば結果が変わりうる**失敗だけ。
要求そのものが不正なら、何度送っても不正なので再試行しない。

| 失敗 | 再試行 | 理由 |
|---|---|---|
| 接続タイムアウト | する | 相手に届いていない可能性がある |
| 読み取りタイムアウト | **条件付き** | 届いている可能性があるので、冪等キー必須 |
| 5xx | する | 相手側の一時障害 |
| 4xx | しない | 要求が不正。再送しても同じ |
| 429 | する | ただし `Retry-After` に従う |

## パラメータ

- 初回待機 200ms、倍率 2.0、上限 3 回、ジッタは待機時間の ±20%
- 全体の締め切りは 30 秒。これを超えたら再試行の途中でも打ち切る

ジッタを入れるのは、同時に落ちた呼び出し元が同じ瞬間に一斉再送して相手を二度殺す
のを避けるため。均等な指数バックオフは、障害からの復旧を最も邪魔する。

## 読み取りタイムアウトの扱い

読み取りタイムアウトは「届いたかどうか分からない」状態であり、再試行すると二重課金の
可能性がある。冪等キーが付いている呼び出しに限り再試行してよい。

決済 API はすべて冪等キーを必須にしているので、この条件は常に満たされる。
外部 PSP への呼び出しでは PSP 側が冪等キーに対応しているかを個別に確認すること。

## やってはいけないこと

- 台帳への書き込みを再試行すること。台帳は追記のみなので、再試行は二重計上になる
- 再試行の回数をリクエストごとに変えること。運用時に挙動が読めなくなる
